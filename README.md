# 抖音手表助手 · 电脑端桥接服务

> English: [README.en.md](README.en.md)

在电脑上常驻一个可见的 Chromium 会话，把抖音私信的能力暴露给配套的 HarmonyOS 手表客户端
[`watch-client`](https://github.com/qbw101/watch-client)。**手表不直接连抖音**：所有抖音操作
都由这里的浏览器完成，手表只是一个省电、交互顺手的手柄。

链路是**自研的二进制帧协议**（有意不用 HTTP），走裸 TCP 长连接，端口默认 `8787`，
应用层再做一层 X25519 + AES-256-GCM 加密。

## 能做什么

| 能力 | 说明 |
| --- | --- |
| 常驻抖音会话 | 启动时开一个可见的 Chromium 窗口登录抖音私信页，整个进程只开这一个 |
| 会话名单 | `config.json` 里的 `friends` 决定手表上列出哪些会话，配置页可以「从抖音读出来勾选」 |
| 读消息 | 按 rev 做增量：内容没变就回一个 rev，变了才传正文 |
| 发消息 | 文字与原生表情；发送后盯住气泡等确认，避免「假成功」 |
| 主动推送 | 服务端轮询浏览器，内容真的变了才推一帧给手表，手表不做 2 秒轮询 |
| 图片下发 | 表情缩略图与聊天图片在服务端降采样后再传，穿透带宽下省一个数量级 |
| 表情库 | 读抖音表情面板（含自己收藏的自建表情），落盘缓存缩略图 |
| 扫码登录 | 配置页上发起扫码登录、看当前登录的是谁、退出登录 |
| 配置页 | 端口 / 令牌 / 图片边长 / 启动行为都能在网页上改，不用记命令行参数 |

## 架构

```
┌──────────────────────────────┐
│ 华为 WATCH 5（watch-client）  │
│  裸 TCP 长连接 + 二进制帧      │
└───────────────┬──────────────┘
                │ 局域网 TCP（默认 8787）
                │ X25519 握手 + AES-256-GCM
┌───────────────▼──────────────────────────────────────┐
│ 电脑：本工程                                          │
│                                                      │
│  scripts/watch_server.py        启动入口 / 日志 / 配置页 │
│    └─ bridge/tcp_server.py      每连接一线程：解帧→分发  │
│         ├─ 读循环        只做分帧和分发                 │
│         ├─ 推送线程      订阅的会话变了才推              │
│         └─ 线程池        慢操作（读会话/发消息/拉图）     │
│              └─ bridge/session.py                     │
│                   └─ 常驻 Chromium ──► 抖音私信页       │
│                                                      │
│  bridge/setup_web.py            配置页（只绑 127.0.0.1）│
└──────────────────────────────────────────────────────┘
```

### 三个刻意的设计

**为什么不用 HTTP。** 穿透服务商是按「应用协议」判定的：走 HTTP(S) 隧道要备案域名，
走 TCP 隧道但应用协议是 HTTP 又只能用非内地节点（境外节点速度差）。自研二进制帧在服务商侧
看不出任何 HTTP 特征，于是可以走内地节点的 TCP 隧道。另外 HTTP 的短连接 + 2 秒轮询在手表上
是纯浪费：每条请求都要重新握手、带一整套请求头，而绝大部分轮询的结果是「什么都没变」——
白白唤醒一次无线电。长连接天然支持服务端主动推送，这才是能换掉轮询的前提。

> 要让手表离开家里 Wi-Fi 后也能连上，请用穿透服务商的 **TCP 隧道**（不是 HTTP 隧道），
> 走内地节点。也不要把服务绑到自有域名上做 CNAME —— 域名一旦指向内地节点就回到备案范围了。

**读循环只做分帧和分发。** 任何会阻塞的操作（读会话、发消息、拉图）都丢给线程池。
否则一个慢请求会把这条连接上所有的帧都堵住，心跳也发不出去。

**图片在服务端降采样。** 穿透带宽通常只有 1~5 Mbps，而 65 张表情原图合起来 7.3 MB，
首屏要等一分钟。缩到显示所需的分辨率后总大小降一个数量级。表情缩略图还会按「一次落盘」的
方式缓存（原图里有 1 MB+ / 71 帧的动图，而手表上它只是一个 70 来 px 的静态格子）。

## 安装与启动

```bash
pip install -r requirements.txt
python -m playwright install chromium     # 只做一次，下载浏览器内核
```

启动：

```bash
# Windows：双击即可（内部会切工作目录、关控制台快速编辑模式、清残留锁文件）
run_watch_server.bat

# 或者手工
python scripts/watch_server.py
```

命令行参数：

```bash
python scripts/watch_server.py                     # 默认 0.0.0.0:8787
python scripts/watch_server.py --port 9000         # 换端口
python scripts/watch_server.py --token mytoken     # 指定令牌
python scripts/watch_server.py --crypto plain      # 关掉加密（仅排障用）
python scripts/watch_server.py --host ::           # 双栈监听，顺带接受 IPv6
python scripts/watch_server.py --setup             # 顺手在浏览器打开配置页
```

配置来源与优先级：**命令行 > 环境变量 > `server_config.json` > 内置默认值**。

启动后会打开一个抖音浏览器窗口，**请保持它和这个控制台窗口都开着** —— 关掉 Chromium 等于
断掉抖音会话，得重启服务。日志同时写控制台和 `artifacts/tcp_server.log`。

> **首次运行放行防火墙。** Windows 防火墙的入站规则是按「程序路径」匹配的，
> 换了 Python 解释器（换虚拟环境）规则就失效，局域网来的包会被默认丢弃 —— 这一点在电脑本机
> 测不出来，因为连 `127.0.0.1` 走环回、不过防火墙。右键 `allow_lan_firewall.bat` →
> 「以管理员身份运行」按端口放行 8787。

## 配置页

首次启动会**自动打开**一个本机配置页；之后服务运行期间它持续可用（地址不变，端口从
`8788` 起顺延），要重新打开就加 `--setup` 或直接访问 `http://127.0.0.1:8788/`。

> 配置页**只绑 `127.0.0.1`**，同一个进程里的另一个监听（8787）才对局域网开放。
> 这两件事不要混在一个监听上。

七个分区：

| # | 分区 | 内容 |
| --- | --- | --- |
| 1 | 手表端需要填写的两项 | 显示本机局域网地址与访问令牌，照录到手表上 |
| 2 | 抖音账号 | 当前登录的是谁（昵称 / 头像 / uid）、发起扫码登录、退出登录 |
| 3 | 手表上显示哪些好友 | 可从抖音私信列表读出来勾选，写回 `config.json` 的 `friends` |
| 4 | 连接设置 | 监听地址、端口、访问令牌、链路加密开关 |
| 5 | 图片下发 | 表情缩略图边长、聊天图片边长 |
| 6 | 启动行为 | 启动时是否自动打开配置页 |
| 7 | 当前状态 | 只读信息：协议版本、监听地址、就绪状态等 |

几个行为约定：

- **写前先校验，验不过一个字都不写。** 端口是整数且在 1~65535、令牌不能有空格、
  好友名单不能为空 —— 校验失败时留在页面上把原文给你，不会静默覆盖成默认值。
- **连接设置改完需重启服务生效**（页面上会标出来）；图片边长同理。
- **好友名单只改 `friends` 这一个键**，文件里别的键原样保留。
- 配置坏了**不拦启动**：`server_config.json` 解析失败会改名留档为
  `server_config.json.bad` 再用默认值，事后还能把自己的设置捞回来。

## 手表端填什么

配置页第 1 区会直接列出两行，照录：

| 字段 | 值 |
| --- | --- |
| 电脑地址 | `电脑局域网IP:8787`（不写端口默认为 8787） |
| 访问令牌 | 8 位十六进制串，由服务端首次启动时生成 |

令牌同时会同步一份到 `artifacts/watch_token.txt`。两样都在手表本地持久化，改的话在手表
列表页点右上角的**设**。

## 链路协议

帧头固定 **8 字节，大端**：

| 偏移 | 长度 | 字段 | 含义 |
| --- | --- | --- | --- |
| 0 | 4 | 长度 | 载荷字节数（不含帧头本身） |
| 4 | 1 | 类型 | 见下表 |
| 5 | 2 | 请求 id | `0` 表示服务端主动推送、无对应请求 |
| 7 | 1 | 标志 | 见下表 |

类型：

| 值 | 名称 | 方向 |
| --- | --- | --- |
| `0x01` | `HELLO` | 客户端带 token 握手，服务端回 ok |
| `0x02` | `REQ` | 客户端 → 服务端 |
| `0x03` | `RES` | 服务端 → 客户端（应答或主动推送） |
| `0x04` | `IMAGE` | 服务端 → 客户端：图片二进制 |
| `0x05` | `PING` | 任一方 |
| `0x06` | `PONG` | 任一方 |

标志：`FLAG_MORE = 0x01`（IMAGE：后面还有属于同一张图的帧）、`FLAG_ERROR = 0x02`
（RES：载荷里是错误信息）、`FLAG_PUSH = 0x04`（RES：服务端主动推送）。

常量：`PROTOCOL_VERSION = 1`、`MAX_PAYLOAD = 4 MB`、`HELLO_TIMEOUT_SECONDS = 10.0`。
握手双方版本不一致时直接拒绝，避免新旧实现按不同的约定解析同一串字节。

### 指令表（`REQ` 载荷里的 `op`）

| `op` | 作用 |
| --- | --- |
| `status` | 服务是否就绪、当前会话是谁 |
| `messages` | 读某个会话的消息（带 `rev`，增量） |
| `send` | 发文字或表情；直接回传最新消息列表，省一次往返 |
| `conversations` | 读会话列表 |
| `image` | 取一张图（表情 / 聊天图片），降采样后下发 |
| `sticker_thumbs` | 批量取表情缩略图，一次往返把整库给手表 |
| `refresh_stickers` | 手动刷新表情库（手表端「刷」按钮） |
| `sync_stickers` | 打开表情面板时踢一脚的「保鲜」，非阻塞 |
| `watch` | 订阅某个会话，内容变化时服务端主动推 |
| `unwatch` | 取消订阅 |

### 协议层要注意的

- **加密必须串行。** nonce 由「方向前缀 + 计数器」构成，并发加密会撞 nonce，
  撞了直接断连且**不留日志**。`bridge/crypto.py::SecureChannel` 是单线程使用的。
- **载荷再套一层 AEAD**：X25519 密钥交换 + HKDF-SHA256 + AES-256-GCM，帧头保持明文 ——
  帧头只泄露长度，换来的是分帧可以完全不依赖加密层状态。
- **认证靠预共享的 token**，token 不参与密钥派生，只在握手阶段做一次常数时间比对。
  每次连接都换一对临时密钥，所以录下的流量事后拿到 token 也解不开（前向保密）。
- **TCP 是字节流**，绝不能假设「一次回调 = 一帧」，收到什么都要先丢进分帧器攒着切
  （粘包、半包都在那里被吃掉）。服务端用 `bridge/protocol.py::FrameReader`。

想验证实现是否正确，用自带的两个脚本：`scripts/tcp_smoke.py`（这条链路通不通）与
`scripts/tcp_watch_sim.py`（把手表端的调用时序在电脑上复现一遍，逐条验证服务端契约）。

## 表情库

抖音表情面板里的表情没有名字，自建表情更是只能按「第几栏第几个」定位，所以表情库是
**扫描产物**，落盘在 `watch_stickers.json`，缩略图落盘在 `artifacts/stickers/`
（原图）与 `artifacts/sticker_thumbs/`（派生小图）。

- 原图 URL 带签名参数，过一段时间就 403。扫描时顺手把二进制存到本地，之后手表读本地文件，
  既快又不会过期。
- `artifacts/sticker_thumbs/` 是**纯缓存，随时可以整个删掉**，删了会按需重新生成。
- 服务运行时会顺手刷新表情面板（不用停服务、也不用第二次登录，少一次风控暴露面），
  刷新完库文件的 mtime 变化会让推送循环自动把新状态推给手表。
- 离线扫描仍然可以单独跑：`python scripts/scan_stickers.py`，但它必须独占
  `artifacts/run.lock`，也就是得先把服务停掉。
- 想肉眼核对「手表上该看到哪些表情」，用 `python scripts/make_sticker_board.py` 把库渲染成
  一张可视化清单 —— 在表上清点 66 个格子不现实。

## 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 服务跑到一半卡死，敲两下键盘就恢复 | Windows 控制台**快速编辑模式**：控制台进入选择态后任何写操作都会阻塞，而 Python 的 `logging` 带锁，一个线程卡住就把所有线程堆在锁上。`bridge/console.py` 已在启动时关掉该标志；**不要删这个模块** |
| 手表连不上电脑 | ① 服务没启动；② 不在同一网段；③ 防火墙没放行（见上，本机测不出来） |
| 提示令牌无效 | 两边对不上。以配置页上那份为准（`artifacts/watch_token.txt` 同步一份） |
| 启动就报端口占用 | 换端口，或在配置页改。配置页自己的 8788 起顺延，不用管 |
| 启动报锁文件被占用 | 上次被强制中断（关控制台窗口、结束进程）导致 `finally` 没跑。已由 `scripts/clear_stale_lock.py` 在启动时清理；手工清也行 |
| 二维码扫了没反应 | 登录一律**起子进程**跑 `scripts/login_auto.py`，子进程崩了或用户不扫都不会连累服务。页面会把子进程输出尾部显示出来，看那里 |
| 浏览器窗口关掉后一片报错 | 关掉 Chromium 等于断掉抖音会话，必须重启服务 |
| 手表上看不到刚收藏的表情 | 正常有延迟（推送循环按间隔刷）。想立刻看到就点手表上的「刷」，或调 `refresh_stickers` |
| 表情格子里的图全是空的 | 先在浏览器里验证 `op=image` 能返回图片；打不开说明那一项本来就没有缩略图。可以试 `python scripts/build_sticker_thumbs.py` 重建 |
| 发消息要等好几秒 | 正常。服务端要盯住气泡等确认（最小 2 秒观察窗口），这是防「假成功」的正确性保证 |
| 消息列表读出来是空的 / 报 DOM 不对 | 抖音改版了。用 `python scripts/probe_chat.py` 重新探 DOM 结构，对照 `bridge/reader.py` 顶部的 selector 清单 |
| 手表显示的画面是「电脑预览外壳」 | 手表浏览器一旦以「桌面版网页」渲染，布局视口被撑到 980px 就会误判。`scripts/preview_mode_check.py` 是这个判定的回归测试 |

排错脚本（`scripts/` 下）：

| 脚本 | 用途 |
| --- | --- |
| `probe_endpoint.py` | 探测一个 `IP:端口` 上跑的到底是不是本服务、能不能真干活 |
| `probe_chat.py` | 探测抖音私信页的 DOM 结构，确定 selector |
| `clear_stale_lock.py` | 清残留的死锁文件 |
| `tcp_smoke.py` | 协议的参考实现 + 端到端冒烟测试 |
| `tcp_watch_sim.py` | 复现手表端的调用时序，逐条验证契约 |
| `console_freeze_check.py` | 验证「控制台冻住 → 服务卡死」这条链与修复是否成立 |
| `crypto_concurrency_check.py` | 验证「同一时刻只能有一个线程在加密」这条约定 |
| `bench_bridge.py` / `bench_sticker_images.py` / `bench_watch_image_latency.py` | 性能体检：接口计时、单图耗时、手表按现有时序拉全部缩略图的耗时 |
| `setup_page_check.py` | 配置页的 HTTP 级自检（纯本地，起 127.0.0.1 的真服务打它） |
| `setup_page_ui_check.py` | 配置页的浏览器级走查（Playwright），验「点一下按钮页面会不会乱」 |
| `setup_page_shot.py` | 把配置页渲染成一张图，改 `setup.html` 时不用真跑服务 |
| `make_sticker_board.py` | 把表情库渲染成可视化清单 |
| `verify_sticker_send.py` | 验证「预览的是哪张、发出去的就是哪张」 |

前两个自检脚本需要 Playwright，且**不依赖项目根的真实 `config.json`**（那是运行数据、不进
版本库，自带示例名单），所以 clone 下来就能跑：

```bash
python scripts/setup_page_check.py
python scripts/setup_page_ui_check.py
```

## 工程结构

```
watch-bridge/
├── scripts/
│   ├── watch_server.py          启动入口：日志、参数、配置页、首启向导
│   ├── login_auto.py            扫码登录子进程（自动检测完成并保存凭证）
│   ├── scan_stickers.py         离线扫描表情面板
│   └── …                        自检 / 探测 / 压测脚本（见上表）
├── bridge/
│   ├── tcp_server.py            裸 TCP 服务：每连接一线程、读循环、推送、线程池
│   ├── protocol.py              二进制帧协议（帧头、类型、标志、分帧器）
│   ├── crypto.py                X25519 + HKDF-SHA256 + AES-256-GCM
│   ├── session.py               常驻抖音会话（可见 Chromium + 串行化命令）
│   ├── reader.py                读消息列表（DOM selector 都在这）
│   ├── fastopen.py              切会话：优先点左侧列表，失败回退搜索
│   ├── console.py               Windows 控制台快速编辑模式的处理（别删）
```

## 已知边界

| 边界 | 说明 |
| --- | --- |
| 依赖可见浏览器 | 整个进程只开一个 Chromium 且是可见模式，关掉它等于断掉会话 |
| 单实例 | `artifacts/run.lock` 串行化，同一时刻只允许一个服务持有浏览器会话 |
| 会话数量 | 受 `config.json` 勾选数量限制，勾得多手表列表就长 |
| 自建表情靠序号定位 | 抖音面板里自建表情没有名字，只能按「第几栏第几个」定位；抖音那边增删表情会让序号漂移，需要重新扫描 |
| 自动化的固有风险 | 抖音随时可能改版（DOM、接口），也随时可能收紧风控 |
| 明文 HTTP 已废弃 | 旧版走 HTTP，完整快照留在 `attic/http-v0/`，不再维护。`bridge/server.py`、`bridge/watch.html` 是其中仍被 `check_sticker_api.py` / `preview_mode_check.py` / `sticker_grid_check.py` 引用的两个文件，因此暂时留在原位 |
| 仅供个人使用 | 见下方免责声明 |
